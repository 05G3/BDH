FLOPs Cost Model vs Token Length

Scores form scales as $\mathcal{O}(T^2(N+D))$, whereas state form scales as $\mathcal{O}(2TND)$. At $T=64$, scores form is $\mathbf{5.3\times}$ faster.

Crossover threshold: $T^* = \frac{2ND}{N+D} \approx \mathbf{341\text{ tokens}}$ ($N=512, D=256$).

Pipeline

Each tile is normalised per band with training-set statistics, split into 64 non-overlapping 8×8 patches, embedded, and refined by four weight-tied BDH levels. Average pooling gives one vector per tile.

Input Tile13×64×64
→
Patch Unfold64×832
→
Embedding64×256
→
BDH ×464×256
→
GAP Pool256
→
Linear Head10 Logits

One BDH level, as implemented in models/bdh.py (per head, $N = 512$ internal units, $nh = 4$ heads):

u  = ReLU(x · encoder)                 sparse positive code
ũ  = RoPE(u)                           queries = keys
a  = LN( (ũ ũᵀ) x )                    linear attention, no softmax, no mask
v  = ReLU(a · encoder_v)
g  = Dropout(u ⊙ v)                    multiplicative gate (~93% zeros)
y  = LN( concat_heads(g) · decoder )   N·nh = 2048 → 256
x  = LN(x + y)                         residual, repeated for 4 levels

Limitations

  • This is an adaptation, not a full reproduction of BDH-GPU. There is no time-recurrent synaptic state across patches.
  • Activation sparsity is measured, not assumed; non-negativity from ReLU does not automatically enforce high sparsity without the multiplicative gate.
  • Sensor-specific normalization: trained strictly on Sentinel-2 Level-1C top-of-atmosphere reflectance values.
  • Baseline multi-seed runs (Tier 1–3) are configured in run_suite.py and can be executed as compute allows.
